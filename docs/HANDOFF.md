*Written 2026-11-10 for anyone (human or AI) picking this project up. Everything below is current as of commit `c0cb08b` on `main`.*

## 1. What this is

**Boxster SRS** is an iPhone app (Flutter) that talks to a cheap Wi-Fi ELM327 OBD-II adapter and reads / clears diagnostic trouble codes on the owner's cars. It started as a one-purpose tool — clear the airbag (SRS) fault on a 2014 Porsche 981 Boxster after the passenger seat airbag connector was unplugged — and has grown into a general code reader with a FORScan-Lite-style interface.

## 3. What the app does

Home screen = four tiles over a monospace output pane, CONNECT / DISCONNECT bar, status line (adapter ID + battery volts).

- **Vehicle** — scans the diagnostic CAN: TesterPresent (3E 00) to every 11-bit ID 0x700–0x7FF (powertrain 0x7E0–7E7 behind a settings toggle) and every 29-bit `18DAxxF1`; second-pass probe of known Ford/VW addresses with `10 01`; then identifies each responder (UDS 0x22 on DIDs F187/F191/F197/F189/F19E + F190 VIN, F111/F188/F18C Ford part/sw/serial) and reads its DTCs (19 02 FF). Modules that answer no identification DID are labelled from an address table (Ford HS-CAN and MS-CAN conventions, VW MQB) and marked "by address". After the HS scan, if the adapter has an HS/MS switch (setting, default on), the app asks the user to flip it and scans MS-CAN (ELM protocol B, `ATPB E0 04`, `ATSPB`), then asks them to flip back. Each module remembers which bus it's on; actions on the other bus prompt a flip first.
- **Errors** — all modules with their codes: raw Porsche-style hex, SAE form (B0001-04), status bits, and plain-English text for SAE-generic codes. Default view shows only *active* codes (status & 0x0F ≠ 0); a filter button reveals the inactive "test not completed" entries Ford modules list by the hundreds. Tap a code → 19 04 snapshot / 19 06 extended data hex. Each module has a "Clear codes" button (typed-CLEAR confirmation).
- **Clear SRS** — one-tap clear for the airbag module. Enabled only when exactly one module is flagged airbag. Sequence: 10 03 (fall back to default session), TesterPresent, 14 FF FF FF, handle 0x78 pending, verify 0x54, re-read, report if a fault is still `testFailed`, 10 01.
- **Dashboard** — Mode 01 live data from the PCM/DME (RPM, speed, coolant, IAT, load, STFT/LTFT B1/B2, throttle, module voltage) as gauges, table, and graph. US units by default (mph/°F), Metric in settings.
- **Log** (app bar) — raw AT/CAN transcript; Copy to clipboard; Share as .txt.
- **Settings** (gear) — adapter host/port, include powertrain in scan, adapter has HS/MS switch, vehicle bus (CAN vs K-line legacy), units.

### Airbag recognition
A module is flagged airbag when identification text contains AIRBAG / POSIP / SRS / RESTRAINT, whole-word RCM / SDM / ORC / ACU, a Porsche part number in the `9xx 618 xxx` family, or a Ford `14B321` part base; or when it's at a known airbag address (0x737 Ford, 0x715 VW) and gave no system name. Unknown-address modules with an actively failing B-code are also flagged (the original Porsche fallback). A module at a *known non-airbag* address (Ford APIM, BCM …) can never be flagged by B-codes alone — SYNC throws B-codes.

### Code text
Generic SAE J2012 text for 2,066 codes (P0xxx, P2xxx, P3xxx, U0xxx) is compiled into `lib/core/dtc_table.dart`, generated by `tool/gen_dtc_table.py` from the open-source python-OBD library. Ford / Lincoln / Mercury manufacturer-specific codes get text from **Tony's database** (a friend's compiled Ford code list, normalised): about 19,200 codes / 26,800 meanings in `lib/core/ford_dtc_table.dart`, generated by `tool/gen_ford_dtc_table.py` from `tool/data/ford_dtc_source.csv`. Precedence: primary-source-verified generic text (`lib/core/verified_generic_dtc.dart`, empty for now) → SAE table → Ford list. Ford text is confirmed only on a Ford/Lincoln/Mercury VIN (Settings → Manufacturer code text: Auto by VIN / Ford / Off); on a Mazda it is shown only as "not confirmed for this make". For generic-range codes with several Ford meanings (e.g. B0001) the app shows "N possible meanings" rather than picking one. Candidate text from the Wal33D/dtc-database audit (7,275 generic additions, 41 "Reserved" replacements) and a Porsche DME P-code PDF (DME 5.2.2/7.2/7.8, not the 981) is staged in `tool/data/staged/`, **not bundled**: provenance undocumented, primary sources not yet checked — see that folder's README. Other makes' manufacturer codes (Porsche included) still show "Manufacturer-specific" with no text.

## 4. Safety rules (non-negotiable — also in `CLAUDE.md`)

1. **One transmit choke point.** Every byte sent to the car passes through `Uds.request()` in `lib/core/uds.dart`.
2. **Allow-list only.** CAN mode: 0x01 (Mode 01, only to 0x7E0), 0x10 (sessions 01/03 only), 0x14, 0x19, 0x22, 0x3E. K-line legacy mode: generic Modes 01/03/04/07/09 only.
3. **Never** 0x27 SecurityAccess, 0x2E WriteDataByIdentifier, 0x31 RoutineControl, 0x11 ECUReset, 0x34–0x38 upload/download, 0x10 0x02 programming. If a module answers NRC 0x33 (security required), report it; do not try to satisfy it.
4. 0x14 is refused on functional/broadcast IDs always; on powertrain IDs only the per-module Clear button may send it (`allowPowertrainClear: true`); the Clear SRS tile never can.
5. Every clear requires the user to type `CLEAR`.
6. Service resets, coding, adaptations, PIS/clutch writes etc. are *out of scope by design* — reads and code clears only. Those belong to the factory/pro tool.
7. `test/core_test.dart` asserts the refusals; keep it green.

## 7. Where things stand / open items

1. **Porsche test is the whole point and hasn't happened yet.** Expected flow: CONNECT → Vehicle → one module flagged AIRBAG / POSIP (by Porsche part number 9xx.618.xxx or system name) → reconnect the seat airbag plug (battery off, wait, reconnect) → Clear SRS → type CLEAR → lamp out. If the connector stays unplugged the fault returns immediately; permanently coding the circuit off is a PIWIS job, deliberately not in this app.
2. **Truck: verify the latest build.** Things to confirm: HS scan now picks up ABS 0x760 / RCM 0x737 / PSCM 0x730 / IPC 0x720 via the second-pass probe; RCM flagged airbag; APIM *not* flagged; MS-CAN prompt appears and the 125k scan finds the body modules; Errors shows active codes only.
3. **Maserati:** try "K-line legacy" bus mode — adapter must have K-line hardware (most v1.5 clones do). First connect takes ~15–20 s. Engine codes/clear/live data only. Clutch wear / PIS is handled by the ThinkDiag 2 (Launch) on order, not this app.
4. **Android:** `flutter create` includes `android` so it should build; never tried. Would need `android/` plumbing for Wi-Fi local network and a Codemagic Android workflow.
5. **Nice-to-haves discussed, not built:** freeze frame (Mode 02) in legacy mode; richer per-make module tables; Porsche-specific airbag B-code text once the real code is seen on the car.
6. **Known caveat — airbag flag can over-match (fails safe).** `looksLikeAirbag` (identical to the Python) flags any module at an *unknown* address that has an actively failing B-code, even when its identification names it as something else. On the 981 with the seat plug out, a second body module with a live B-code would also be flagged → two flagged → the Clear SRS tile stays disabled. Workaround on the car: Errors → the POSIP module's own "Clear codes" button (same clear sequence, same typed CLEAR). The same applies after a Ford MS-CAN scan (MS body modules at unlisted addresses with active B-codes). Also, `Module.known` for an MS module falls back to the HS table, so an MS responder at 0x737 would be labelled RCM. Clear SRS does not filter to HS modules; it prompts a switch flip instead. Not changed: the heuristic must stay identical to the Python reference until the real car shows what it needs.
